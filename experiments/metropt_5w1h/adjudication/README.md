# 维护工程师独立裁定包

> 目的:论文的地面真值(事件标签、校准池排除、可见性分层)目前全部由作者团队构建。需要一名在职维护工程师做**盲评裁定**,以界定这层循环性。
> 任务:招募一名在职维护工程师(理想:压缩空气系统/轨道车辆/旋转机械背景)，让其独立完成 instrument/ 中的裁定表单,JSON 落 ratings_in/。
> 预计工作量:**约一个工作日(可拆分)**;详见下方任务分块。

## 裁定任务分块

| 块 | 内容 | 材料 | 预计耗时 |
|---|---|---|---|
| A. 九事件标签 | 对 9 个记录在案的故障事件,独立裁定:故障模式(漏气/漏油)、处置(停运/继续/自愈/维修);**重点两处争议**:① 2022 年两次漏气的部件归因(客户端管路 vs 干燥器先导阀——文献互相矛盾);② 2020 年维护表中重复行号导致的时间戳归属 | 事件文档摘录 + 各事件窗口的遥测摘要(均值/分位数/占空比/LPS 激活) | 1–2 h |
| B. 三次校准排除 | 对被我们排除出名义校准池的 3 个"未记录运行事件"窗口,独立判断:是真实的未记录异常(支持排除)还是普通名义波动(应保留) | 各窗口遥测摘要 + 该车辆的名义基线带 | ~30 min |
| C. 37 正例窗可见性分层 | 对每个故障前窗口的遥测摘要,独立判断:是否存在可据以行动的故障指征(何种)、仅亚阈值前兆、或无任何可行动指征 | 37 个窗口摘要 + 车辆基线 | 2–3 h |

## 盲评纪律(对招募者与材料的要求)

1. 工程师**不得**提前看到:我们的裁定台账、系统输出报告、论文文本或其结论;
2. 材料只含:原始遥测摘要(冻结特征提取)+ 公开发表的文档摘录 + 中立的提问;
3. 争议项以开放式问题呈现(如"你认为 2/28 与 3/23 两次事件的部件归因分别是什么,依据为何"),不提示文献中的两种说法孰是孰非;
4. 完成后我们比对不一致项,**原文披露**分歧(不论多少),不做二次说服;
5. 工程师非作者;自愿参与;可随时退出;不保留个人数据(伦理声明沿用论文措辞)。

## 数据流

1. 工程师打开 `instrument/adjudication_form.html`(待建:自包含、双击即用、
   DOM 构建、逐项导出 JSON,与 rating_form.html 同一模式);
2. 下载的 JSON 放入 `ratings_in/`;
3. 运行 `analysis/analyze_adjudication.py`(待建):输出逐项一致率、争议项清单、
   与作者裁定的分歧表 → 直接喂论文 §7.1(标签取证)与限制第五条。

## 产出如何进论文

- §7.1:独立裁定与作者裁定的一致率(尤其两处争议项的独立裁决);
- 限制第五条:"ground truth author-side" 威胁从"披露"升级为"披露 + 独立界定的分歧";
- 伦理声明增加工程师一句(背景、自愿、时长)。
